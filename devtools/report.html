1. Decision from the collision study

8 base36 chars = 36^8 ~ 2.82e+12 space. At 100,000 distinct strings the measured birthday collision probability is 0.00177, and the measured run needed 0 salted retries at 10k strings. 6 chars (~2.18e+09) already shows a 0.899 probability at 100k; 4 chars (~1.68e+06) collided in the 10k sample and needed 32 retries (5 chars needed 3). 8 is the shortest length that stays comfortably collision-free across all measured populations while saving 24 chars vs the full ~32-char base36 SHA1.

Retry cap = 32. Measured retries are 0 for every length >= 6 at 10k strings, so 32 is far beyond any realistic retry count while bounding an adversarial/saturated-space run to a finite, testable failure (ShortIDCollisionError) instead of an unbounded loop.

  1. loop attempt=0..max_attempts-1

3. How the three decisions interlock

  • Shorter IDs save space but collide more. Length 8 is chosen above; a duplicate truncated digest is resolved by unique_short_id with salted attempts, and saturation raises ShortIDCollisionError — the fallback runs on any real collision, it is not dead code.
  • Cache reuse must not cross templates. The plan key is (template text, sorted field types); a hit that fails the _plans_match rebuild guard is deleted, counted as an invalidation, and recomputed (_format_cached retries exactly once).
  • Concurrent recomputation cannot lose updates. retry_update snapshots (value, version), recomputes, and commits only via compare_and_swap; a concurrent commit bumps the version, rejects the stale write, and forces a fresh retry.
